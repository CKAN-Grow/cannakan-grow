# Grow Platform Architecture

## Purpose

Define the enduring organizational architecture of the Grow platform.

This document explains how Grow transforms canonical truth into understandable experiences.

It does not define individual capabilities.

It does not define individual products.

It does not define implementation.

It does not define user interfaces.

It establishes the permanent organizational model that every future Grow decision shall follow.

## Foundational Question

Answer one question:

How is the Grow platform organized?

## Platform Model

The Grow platform consists of three architectural layers.

Canonical Platform

↓

Products

↓

Presentation

Each layer has one responsibility.

Each layer depends upon the layer beneath it.

Canonical truth never flows upward.

## Rule 1 — Canonical Platform

The Canonical Platform owns truth.

Truth consists of the authoritative concepts defined by the Grow Foundation.

The Canonical Platform is the only source of canonical authority.

Canonical truth never originates from Products or Presentation.

## Rule 2 — Products

Products compose canonical truth into understandable experiences.

Products organize understanding.

Products help people make decisions.

Products never become canonical authority.

Products never redefine canonical truth.

Products exist to make canonical truth understandable, useful, and actionable.

## Rule 3 — Presentation

Presentation delivers experiences.

Presentation owns neither truth nor understanding.

Presentation may evolve independently without redefining either Products or the Canonical Platform.

Presentation exists only to help people interact with Grow.

## Architectural Flow

Truth originates in the Canonical Platform.

Understanding emerges through Products.

Interaction occurs through Presentation.

Each layer serves the layer above it.

No layer replaces the responsibility of another.

## Classification Model

Every future proposal shall first answer one question.

Does it establish or own canonical truth?

If yes:

Canonical Platform.

Does it compose existing canonical truth into an understandable experience?

If yes:

Product.

Does it simply deliver that experience?

If yes:

Presentation.

If it satisfies none of these classifications, it should not become a new architectural layer.

## Architectural Principles

Truth remains canonical.

Products create understanding.

Presentation delivers experience.

Truth is never duplicated.

Understanding never becomes truth.

Presentation never becomes understanding.

Every architectural layer remains independently replaceable and evolvable.

## Governing Documents

The Grow Foundation defines truth.

The Grow Philosophy defines purpose.

The Grow Platform Architecture defines organization.

Together these documents govern every future Grow decision.

Architecture inherits them.

Products inherit them.

Implementation inherits them.
